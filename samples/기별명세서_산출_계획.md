# 행정도·네트웍구성도 → 기별명세서 자동 산출(추출) 계획

작성: 2026-06-16. 양식: `samples/기별명세서양식.xlsx`, 도구: 행정도_설계_샘플.xlsm

**방향 (owner 확정)**: 설계자가 행정도·네트웍구성도에서 작업한 내용을 읽어 **기별명세서 양식의 자재·공종 수량을 자동으로 채운다**(정산 문서 산출). 폼→도식 임포트가 아니라 **도식→폼 추출**.

owner 결정 요약:
- 행정도에 **신설·철거**를 그리고 **거리**를 입력 → 기별에서 추출 (신설→2번 시트, 철거→3번 시트)
- **코어접속**: 설계자가 연결코어를 입력하면 그 수, 미입력이면 **그 연결상태의 최대 코어로 자동 계산**
- **주간/야간**(함체작업 등)도 설계자가 **네트웍구성도에서 입력한 결과를 추출**

## 1. 데이터 출처 (설계 → 폼 열)

| I–AA 케이블(2C~288C, 가공/관로/일반) | 행정도 케이블 규격 → 해당 열에 거리(M) 합산. status로 신설/철거 시트 분기 |
| AB–AI 광접속함체(36~288C·직선·다분기·중간분기) | 행정도 시설물 종류(범례) → 해당 열 개수 |

| GQ 포설(주간)·GS(야간)·GT(이설) | 케이블별 주야/이설 구분(설계 입력) |
| JL 함체·RN·IJP·OFD번호 | 시설물 **배지번호** (owner 2026-06-16) |
| JM 비고 | 시설물 신설/기설 + 종류 = **기설함체·신설함체·기설RN·신설RN** 등 표시 (owner 2026-06-16) |

→ 폼의 **사급/지입 자재 200여 열 중 토폴로지에 있는 것만**(케이블·함체·RN·코어접속·함체작업·포설) 자동 채움. 전주·행거·접지·점퍼·FTTH 부품 등 **물리 자재는 수동 유지**.

## 2. 설계 측 보강 입력 (현재 없을 가능성 — 추출 위해 필요)

| 입력 | 위치 | 비고 |
|---|---|---|
| 함체별 **주간/야간** 함체작업 구분 | 네트웍 함체(또는 시설물 메타) | 폼 HW/HX |
| 코어접속 **주간/야간/성단** 분류 | 네트웍 코어연결(splice) | 폼 ID/IE/IF |

코어 수는 **연결에서 자동**(입력 코어 없으면 케이블 규격 최대 코어로 계산) — owner 규칙.

## 3. 핵심 알고리즘 — 체인 직렬화 (주경로 우선)

폼은 `함체 → 경간거리 → 함체 → …` **선형 행** 구조. 설계는 그래프(시설물+케이블).
- 행정도 케이블 인접관계로 **함체 그래프** 구성.
- **분기 처리 순서 (owner 2026-06-16)**: 분기가 많으면 **주경로 먼저**, 그 다음 **나머지 분기를 큰 쪽부터**.
  - **주경로 = 코어접속(연결) 수가 가장 많은 경로** (말단까지 누적 합). 이 경로를 먼저 `함체→경간→함체` 로 직렬화.
  - 분기점에서 갈라지는 가지들은 각 가지의 **코어접속 누적합**으로 정렬 → **큰 가지부터** 차례로 이어 작성.
  - 재귀: 각 가지 안에서도 같은 규칙(주경로 우선) 적용.
- 경간 행의 케이블 = 직전 함체 ↔ 다음 함체 구간 (규격·거리·여장).
- 신설/철거 status로 2번/3번 시트 분리 출력.

(네트웍구성도 코어구성도 체인 로직과 유사 — 기존 chain 추출 재사용 검토)

## 7. owner 확정 (2026-06-16) — 구현 규칙

### 7-1. 출력 방식 (도구 내 시트 + 내보내기 prepend)
- 3개 기별 시트(종합·신설·철거)를 **도구(.xlsm) 안에 보유**.
- `새파일_내보내기`([M1:3604](M1_Setup.bas)) 확장 — 현재 `행정도`·`네트웍구성도` 를 새 워크북에 복사 후 `행정도(후)`·`네트웍구성도(후)` 로 rename. 여기에 **3개 기별 시트를 두 시트 「앞쪽」에 같이 복사·배치**. 결과 순서: `종합기별명세서 · 기별명세서(신설) · 기별명세서(철거) · 행정도(후) · 네트웍구성도(후)`.
- 즉 내보내기 한 번에 「채워진 명세서 3장 + 설계 후본 2장」 = 5시트.

### 7-2. 입력은 기존 메커니즘 그대로 (신규 UI 불필요)
- **주간/야간**: 기존 **시설물 태그 콤보**(`_fac_tag_` / `_fac_tag_dd_`, [M1:120-124](M1_Setup.bas)) — `함체작업:주간` / `함체작업:야간` 토글. 추출이 이 태그를 읽음.
- **코어접속 수**: `코어접속:N` 태그 값 **우선**, 없으면 그 시설물의 **실제 코어연결(선번박스) 수 자동 계산**(연결상태 최대 코어).

### 7-3. 시설물 종류별 산출 규칙
시설물에서 코어접속(연결)이 발생할 때, **종류별로** 함체작업·코어접속 칸을 채움:

| 시설물 종류 | 함체작업 | 코어접속 |
|---|---|---|
| **RN** | FTTH 광탭작업 = **1** (주간 `IA` 또는 야간 `IB`) | 코어수 → 주간 `ID` 또는 야간 `IE` |
| **접속함체** | 함체작업 = **1** (주간 `HW` 또는 야간 `HX`, **둘 중 하나만**) | 코어수 → 주간 `ID` 또는 야간 `IE` |
| **그 외 시설물** (접속함체·RN 제외) | 없음 | 코어수 → **성단 `IF`** 에만 |

- 주간/야간은 그 시설물의 `함체작업:주간/야간` 태그로 결정.
- 종류 판정: 행정도/네트웍 시설물의 범례(`_범례`)·종류로 RN / 접속함체 / 그 외 분류 (Phase 1 매핑표).

### 7-4. 여장·구간번호
- 공란으로 진행. 폼의 `함체1 → 구간거리 → 함체2` 행 형식 유지 (체인 직렬화 §3 그대로).

### 7-5. 양식 보존 — 속성·수식 절대 불변 (owner 2026-06-16)
- 기존 양식의 **열 속성·수식을 변경하지 않음**. 헤더(1~8행)·소계 SUM 수식·열 폭·숨김 상태·서식 그대로 둔다.
- 채우기는 **함체/경간 데이터 행의 「값 셀」에만 기록**. 소계·합계는 양식의 기존 수식이 자동 계산.
- 행이 부족하면 **양식의 함체/경간 행쌍을 복사(Insert Copied)** 해 늘림 — 수식·서식이 따라옴. 빈 행 raw 생성 금지.
- RN 의 FTTH 함체작업 = 폼 `FTTH 광탭 작업` 열(주간 `IA` / 야간 `IB`) **확정**.

### 7-6. 분기 작성 순서
- §3 의 「주경로(코어접속 최다) 먼저 → 나머지 분기 큰 쪽부터」 로 행 작성 순서 결정.

### 7-7. JL 번호 = 배지번호 (owner 2026-06-16)
- 폼 `JL` 열(함체·RN·IJP·OFD번호)에는 그 함체 행 시설물의 **배지번호**(검색·코어추적에 쓰는 배지)를 기입.
- 추출 시 시설물 도형의 배지번호를 읽어 해당 함체 행 JL 셀에 기록.

### 7-8. 비고(JM) = 신설/기설 + 종류 (owner 2026-06-16)
- 폼 `JM` 비고 열에 시설물의 **신설/기설 + 종류** 표시: `기설함체` · `신설함체` · `기설RN` · `신설RN` 등.
- 같은 분류가 A열 행 라벨(`기설함체1`·`신설함체2`…)도 결정 → A(순번 포함)·JM(비고) 둘 다 같은 신설/기설+종류로 채움.
- 출처: 시설물의 신설/기설 상태 + 종류(함체/RN). 도구 확인(Phase 1): `_시설물` 메타 col2 구분라벨 첫 토큰("신설/가공"→"신설"). 종류는 `시설물_isRN` + 범례.

### 7-9. 기설 구간 거리 제외 — 공종만 (owner 2026-06-16)
- **기설접속함체 → 기설케이블 → 기설접속함체**(기설시설물-기설케이블-기설시설물) 구간은 **경간거리(거리/포설) 미반영**.
- 그 구간의 **공종만** 가져옴 (기설 함체의 코어접속·함체작업은 정상 추출). 기설 케이블 거리는 정산 미반영 — 앞의 「기별명세서 정산 규칙」과 일관.
- 적용: 케이블 status='기설' → 경간 거리/포설 칸 공란, 양끝 기설 함체 공종은 정상. 신설→신설시트 거리 반영 / 철거→철거시트 거리 반영.
